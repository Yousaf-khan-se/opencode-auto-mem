## Project Goal

**Maintain and improve the `opencode-auto-mem` plugin** — a patched version of `@npv12/opencode-memory-md` that uses the stable OpenCode plugin API.

The plugin is installed and working in OpenCode. This workspace contains the full source code for modification and improvement.

## OpenCode Plugin SDK — Critical Knowledge (READ BEFORE ANY API CHANGES)

**Installed SDK:** `@opencode-ai/plugin@1.18.27` (already in `node_modules/` — do not delete)

### API surface of the installed SDK (verified by reading its .d.ts files)

| Entry point | Shape | Usable for this plugin? |
|-------------|-------|-------------------------|
| `@opencode-ai/plugin` (root) | `Plugin = (input: PluginInput, options?) => Promise<Hooks>` — async function returning a hooks object | ✅ YES — supports `tool` registration AND `experimental.chat.system.transform`. **This is the stable API and exactly what our plugin uses.** |
| `@opencode-ai/plugin/v2/promise` | `define({ id, setup(ctx) })` | ❌ NO — its `PluginContext` only exposes `options, agent, aisdk, catalog, command, integration, plugin, reference, skill`. **No tool registration, no system transform.** |
| `@opencode-ai/plugin/tui` | `Plugin.define()` with full context (`ui`, `data`, `client`, `router`, ...) | ❌ TUI-only plugins (CLI rendering, routes, slots, tabs). |
| `@opencode-ai/plugin/v2/effect` | Effect-native variant (`ctx.session.hook`, `ctx.storage`, ...) | ❌ Different runtime, requires `effect` package; revisit later. |

### Rules

- **DO NOT migrate the server plugin to `Plugin.define()` from `v2/promise`** — it would break tool registration and memory injection.
- **`opencode-plugin-creation-doc/plugin.md` documents OUR stable API** (async function → hooks). `opencode-plugin-creation-doc/v2/` describes TUI/Effect/V2 plugins — reference only. For server-plugin questions, read the installed SDK's type files — `node_modules/@opencode-ai/plugin/dist/index.d.ts` contains the `Hooks` interface listing EVERY available hook (`chat.message`, `chat.params`, `tool.execute.before/after`, `permission.ask`, `event`, `experimental.*`, ...).
- **Untapped stable-API hooks relevant to this plugin:** `event` (all server events — e.g. `session.idle` is the natural hook for future session-level memory; `session.compacted` and `session.error` are now logged), and `experimental.session.compacting` (**now implemented** — injects memory-state context into the compaction prompt). `client.app.log()` structured logging is **now adopted** (dual-sink `plog` in `src/logger.ts`; `initPluginLogger(input.client)` is the first statement of the plugin body).
- **Background agents ARE possible (verified in bundled @opencode-ai/sdk types):** `input.client.session.create({ body: { title } })` + `client.session.promptAsync({ path: { id }, body: { parts, agent?, system?, tools?: {[name]: boolean} } })` fires a server-side agent run in an independent session — the core primitive for a future memory-keeper. Read results via `client.session.messages({ path: { id } })`, clean up via `session.delete`. Trigger points: `event` → `session.idle` (fires per completed turn — needs debounce + skip-tagged-sessions guard against infinite spawn loops) or `session.compacted` (post-compaction summary harvest). Caveats: idle ≠ session end, every run costs one LLM call, background sessions appear in the TUI session list, `agent` must exist in user config (or use `system`+`tools` whitelist to constrain a standard agent).

### Verified OpenCode internals (v1.18.27 source, github.com/anomalyco/opencode tag v1.18.27) — DO NOT TRUST SECONDARY SOURCES ON THESE

Internet research (blog posts, AI summaries) gave **wrong answers on both points below**. These were verified by reading the actual source of the exact installed version:

- **`tools` body param is a BLOCKLIST, NOT a whitelist.** `session/llm/request.ts` `resolveTools()`: base tools = the agent's configured set; the request map can only DISABLE (`false`); unspecified or `true` = stays ENABLED. So `tools: { memory: true }` leaves bash/edit/etc fully armed. **Correct keeper approach (2.1.0):** enumerate tools at runtime via `client.tool.ids({ query: { directory } })` FIRST (lists every builtin + dynamically registered tool id, no provider/model needed) and set EVERY id `false` except `memory: true`. If `tool.ids` is unavailable, fall back to `client.tool.list({ query: { provider, model, directory } })` (requires `config.model`). If an enumeration path was available but yielded nothing → **fail-closed**: abort the spawn BEFORE `session.create` (hardcoded negatives can never cover dynamic MCP tools — the delegate-escape incident). If no enumeration is possible at all (no tool domain / no model), fall back to the extended hardcoded negatives (incl. the `delegate` family, `background_output`, `background_cancel`, `killshell`).
- **`system` body param is APPENDED LAST, does NOT replace.** `LLMRequestPrep.prepare()`: final system = [agent.prompt || provider-prompt, ...pipeline system, **user.system appended last**] joined by `\n`. And `experimental.chat.system.transform` **fires for ALL sessions including plugin-spawned ones** — our keeper must be detected and skipped in system.transform or it gets the full memory context + main-agent instructions injected (token waste + conflicting instructions). Bonus: last-position text is the strongest instruction position.
- **Plugin lifecycle:** ONE plugin instance per OpenCode server process (shared worker), loaded at startup; hooks receive per-call context (sessionID, directory). In-memory state (maps, timers) is safe within one server; on server restart it resets. Multiple concurrent sessions share the instance. Sessions created via API can target any `query.directory`. **Consequence:** the plugin's startup cwd ≠ each session's directory — per-session project resolution (from `context.directory` / session's directory) is REQUIRED for multi-project correctness. Two servers on one memory dir = two plugin instances (best-effort file lock in state file mitigates double-spawning).
- **Event shapes (bundled SDK types.gen):** `session.idle` / `session.compacted` carry only `{ sessionID }`. `session.created`/`session.updated` carry the full `Session { id, projectID, directory, parentID?, title, time{created,updated,compacting?}, ... }` — free sessionID→directory mapping.
- **`promptAsync` `model` field is `{ providerID, modelID }` only** — no variant (thinking/non-thinking) support in this API version; store it in config but document it applies only when the SDK adds support.

### Memory-Keeper Architecture (added this session — single-writer model)

**Purpose:** offload project-memory writing from the main agent to a dedicated background keeper so the main agent focuses on the user's task. Main agent keeps ALL reads, writes global files (MEMORY/IDENTITY/USER), and signals memory-worthy content via `<mem></mem>` tags in its replies.

- **Trigger:** `event` → `session.idle` per-turn delta harvesting (Mode A). Debounce (default 30s, config) + dirty-flag coalescing (idle while keeper running → one respawn after completion). **Every turn re-harvests:** `onKeeperIdle` clears the parent from the `running` set on harvest completion (2.1.0 — pre-fix the keeper was one-shot per session). Timeout 5 min → abandon, checkpoint NOT advanced → next idle retries. Startup sweeper: harvest unharvested tails of past sessions (cap 3, config); **skips `[mem-keeper]`-titled sessions via session.list data** (restart-safe, zero extra API calls) and logs every skip decision with canonical vocabulary (`skip-no-directory`, `skip-home`, `skip-keeper-fast`, `skip-keeper-title`, `skip-no-project`, `skip-already-harvested`, `swept`). Known residual (accepted): delegation/agent-child sessions carry no `[mem-keeper]` title and remain sweeper-eligible — one-time noisy harvest.
- **Delta/checkpoints:** `client.session.messages(parentID)` → messages after last checkpoint message ID; persisted per project in `keeper-state.json` (atomic, gitignored). Empty delta (no new user/assistant text) → skip. `<mem>` tags in assistant replies = high-priority keeper signal.
- **Loop guard (two layers):** in-memory spawned-set (primary, fast) + title prefix `[mem-keeper]` via `session.get` fallback (survives restarts). `system.transform` skips keeper sessions (they get only the keeper prompt via `system` body param, appended last). Restart-hole verdict: `session.created` fires before the first LLM request, so the fast guard always covers live keepers; a keeper orphaned by a mid-harvest restart never receives another LLM request — verified not a gap, no code change.
- **Spawn pipeline:** `session.create({ parentID, title: "[mem-keeper] ...", query.directory })` → `promptAsync({ system: keeperPrompt, tools: dynamicBlocklist, model: config.keeper.model ?? session default })`. Tool sandbox = `tool.ids()`-first enumeration with fail-closed abort (see the blocklist rule above).
- **Keeper sessions:** fresh per harvest (NOT a singleton — singleton context grows forever, relies on compaction, drifts). Parented to the main session (TUI lineage), in the parent's directory. Auto-delete after success is config (`deleteSessions`, **default true since 2.2.0** — each dead keeper session otherwise stays in the OpenCode server's memory + session list forever; the audit trail survives in git commits + keeper-state.json).
- **Write guard:** when keeper enabled, write/edit/delete on project targets from non-keeper sessions → rejected with guidance to use `<mem>` tags. Global targets unaffected. Config `enabled: false` → full fallback to old behavior (main agent writes, original instructions).
- **Config file (v2 schema, 2.3.0):** `keeper-config.json` at memory root. Optional `mode` preset (`minimal|tags|balanced|full|hybrid|offline` — `balanced` = pre-modes behavior) + granular knobs: `{ mode, keeper: { enabled, model: { providerID, modelID }, deleteSessions, sweeperMax, trigger: { mode: idle|tags|always|manual|compaction, debounceMs, alwaysDebounceMs, immediateOnTags, fallbackToIdle }, harvest: { scope: delta|tagsOnly|full, maxTranscriptChars, minDeltaChars } }, indexing: { enabled, trigger: search|debouncedWrite|manual, writeDebounceMs, dtype: int8|fp32, topK, keywordFallback, scope: project|all }, writeGuard }`. `resolveConfig()` (pure, exported) layers explicit knobs over preset overrides over BALANCED defaults; per-knob validation (invalid → that knob's default + warn, valid siblings preserved). Legacy flat keys (`keeper.debounceMs`) still honored. `loadKeeperConfig()` hot-reloads via mtime+size cache (`__resetKeeperConfigCache()` test hook). Trigger-mode gating is WIRED (Phase 2): `spawnKeeper()` runs a tags gate (mode `tags`: no `<mem>` in delta + no `fallbackToIdle` → checkpoint advances WITHOUT harvest — reuse of the advance-without-spawn pattern); `onMainSessionIdle()` no-ops in `manual`/`compaction`; sweeper only sweeps in `idle`/`always`; new entries: `spawnNow()` (public, bypasses gates — backs the memory tool `harvest` action), `onSessionCompacted()` (compaction-mode entry, routed from the `session.compacted` event in index.ts). `src/memTags.ts` = pure `<mem>` extraction (`extractMemTags`, `buildTagScanText` — prev-message tail prefix closes the checkpoint-boundary gap). Phase 3 (message-level triggers) is WIRED: `onAssistantMessageCompleted(info)` handles `message.updated` (verified SDK shape: `properties.info: Message` = `{id, sessionID, role, time.completed?}` — NO text); `always` mode schedules via `scheduleAlwaysHarvest()` (separate `alwaysTimers` map, `alwaysDebounceMs` coalescing); `immediateOnTags` consumes text accumulated by `observeAssistantText()` from `message.part.updated` (`assistantTextBuffers`: per-messageID, 8KB tail, 200-entry cap, deleted on completion) and cancels the pending idle timer; spawn-loop guard (`spawned.has`) protects against keeper-reply feedback; index.ts routes both event types (guarded by `keeper.isEnabled()`). Phase 4 (harvest scopes) is WIRED in `spawnKeeper()`: `<mem>` tags extracted ONCE (reused by tags gate + minDeltaChars exemption + tagsOnly scope); `minDeltaChars` guard skips tiny untagged deltas (checkpoint advances; manual + tagged exempt); scope `tagsOnly` → `formatMemTags()` numbered candidates (zero candidates → advance + skip); scope `full` → `formatTranscript(msgs)` whole session (can correct older memory); `capTranscript()` enforces `maxTranscriptChars` with an explicit truncation marker in EVERY scope; `buildKeeperPrompt(project, index, scope)` selects the task-paragraph variant (delta default unchanged — test (l) contract holds). Phase 5 (indexing modes) is WIRED: `MemoryManager` takes `IndexingConfig` (constructor or hot-swappable `configureIndexing()`); write paths call `scheduleIndexRefresh()` (debouncedWrite: ONE coalescing timer per manager, armed only by actual writes — never at boot; `onIndexRefresh()` test hook); `ensureIndexed()` no-ops when `indexing.enabled=false` or `trigger=manual` (reindex ALSO gated since 2.4.5: `handleReindex` early-returns and `embedAllExistingFiles()` carries its own enabled guard — the model never loads while indexing is off; the built index is left on disk for later re-enabling); `semanticSearch()` routes indexing-disabled queries to `keywordSearch()` (pure term-overlap scoring over chunkMarkdown chunks, no model) when `keywordFallback`, else returns an explicit disabled entry; `topK` is the default AND hard cap; `dtype` flows through the pure `src/embeddingConfig.ts` state module (keeperConfig re-exports `configureEmbedding`; `embedding.ts` reads `getActiveDtype()` at pipeline init; `__resetEmbeddingForTests()` drops the loaded embedder); tool execute re-syncs indexing config via the hot-reload cache (reference equality) so knobs apply live.
- **Files:** `src/keeperConfig.ts` (config load), `src/keeperPrompt.ts` (prompt builder + transcript formatter), `src/keeper.ts` (KeeperManager: state, guards, debounce, spawn, sweeper). Tool execute resolves project from `context.directory` (fixes latent multi-directory bug).
- Tool args use Zod-style `tool.schema.*` from `@opencode-ai/plugin/tool`.

### Current (correct) server-plugin pattern

```typescript
import { tool } from "@opencode-ai/plugin/tool";

const memoryPlugin = async (input: { directory: string }) => {
  // ... setup code ...
  return {
    // System prompt injection
    "experimental.chat.system.transform": async (_input, output) => {
      output.system.push(memoryContext + instructions);
    },
    // Tool registration
    tool: {
      memory: tool({
        description: "...",
        args: { /* tool.schema.enum(...).describe(...), etc. */ },
        async execute(args, context) { /* returns string */ },
      }),
    },
  };
};

export default memoryPlugin;
```

**Key differences from the old beta API (still true):**
- No `Plugin.define()` — export async function directly
- No `ctx.session.hook()` — return hooks in object
- No `ctx.tool.transform()` — return `tool: { name: tool({...}) }`
- Tool args use Zod schemas (`tool.schema.*`) instead of JSON Schema
- Execute returns string instead of `{ output: { result }, content: result }`

### How auto-injection works

`"experimental.chat.system.transform"` in `src/index.ts` runs for EVERY chat session:
1. `buildContext()` — bootstrap needed → inject `BOOTSTRAP.md`; otherwise inject `MEMORY.md` + `IDENTITY.md` + `USER.md` (via `MemoryManager.getContextFiles()`) **plus a `## Project Memory Index` section** with the rendered heading indexes of the three project files. The project folder + templates are auto-created on the first session in any directory except the home directory (`isHomeDirectory()` guard in `config.ts`); creation failures are caught and logged so the hook never throws.
2. `getMemoryInstructions()` — `BOOTSTRAP_INSTRUCTIONS` or `MEMORY_AWARENESS_INSTRUCTIONS`.
3. Combined text is pushed into `output.system[]`.

### Compaction protection (added this session)

`"experimental.session.compacting"` in `src/index.ts` appends to OpenCode's **default** compaction prompt (never replaces it — `output.prompt` stays unset):
- `buildProjectIndexForCompaction()` — fresh heading index of the three project files (served from the mtime cache) + skip rules: null during bootstrap, when no project name is resolvable, or in the home directory.
- `buildCompactionContext(projectName, indexSection)` (`memoryInstructions.ts`) — the "Memory State" snapshot + 5 summarization rules: preserve unsaved session knowledge verbatim (facts/decisions/corrections/environment), preserve task state + next steps, one-line refs for already-saved facts, summary framed as "what happened beyond what memory holds" (post-compaction agent gets full memory context re-injected via system.transform, so no re-injection needed here).
- Wrapped in try/catch — this hook must never throw (same rule as `buildContext()`).

`event` hook (added this session): logs `session.compacted` / `session.error`; scaffolding for future session-level memory (`session.idle`). `experimental.compaction.autocontinue` is deliberately left at default (`enabled: true`).

## Heading Index & Section Addressing (added this session)

**`src/headings.ts`** (pure, no fs) — the single source of truth for heading logic:
- `buildHeadingIndex(content)` → `HeadingNode[]` tree (H1–H6, **code-fence aware** — `#` lines inside ``` fences are not headings). Each node: `level, title, directWords/Chars, totalWords/Chars (cumulative subtree), startLine/endLine (1-based, inclusive), children`.
- `findSection(roots, headingPath)` → strict lookup; errors list available siblings; legacy duplicate siblings disambiguated with `"Title#2"` ordinal suffix.
- `findDeepest(roots, headingPath)` → tolerant prefix walk used by the `createMissing` write flow.
- `extractSection(node, content)` → heading + whole subtree markdown.
- `insertUnderHeading(content, node, text)` → inserts at the end of the node's direct content zone (before subsections).
- `renderIndexText(fileName, roots)` → compact `├─ Title (direct/total)` tree for prompts.

**`src/indexCache.ts`** — mtime+size keyed JSON cache. Per-project: `memory/project/{name}/index-cache.json`; global targets: `memory/index-cache.json`. Cache miss → rebuild + persist (atomic). `.gitignore` in the memory repo (written by `git.ts ensureGitRepo`) excludes `index-cache.json` from `git add .`.

**Addressing conventions (locked design):**
- `headingPath: string[]` **includes the document's H1 title** — e.g. `["Environment Memory", "Commands"]`. All H1–H6 are addressable.
- Section `read` returns the whole subtree; `write` inserts directly under the heading line (before subsections), timestamp-stamped like appends; `edit`/`delete` scope `oldString` to the section subtree, must match exactly once.
- `write` to a missing heading errors with sibling suggestions unless `createMissing: true`.
- New `index` action works for ALL targets; write responses include the file's fresh mini-index (freshness piggyback).
- Injected project indexes are ALWAYS included — `buildContext()` auto-creates the project folder + templates (except home directory) before rendering; empty templates show 0/0 counts (progress clue).

**`src/chunker.ts`** was rebuilt on the shared parser: one chunk per heading's direct content, `heading` field is the full path string (`"Corrections > Auth Module"`) — improves semantic-search section targeting. `Chunk` interface unchanged → `vector-store.ts` untouched.

## Tool: memory

**Actions:**
| Action | Description | Parameters |
|--------|-------------|------------|
| `index` | Get the heading index (TOC with word counts) | `target`, `projectName` (optional) |
| `read` | Read a memory file, or one section via `headingPath` | `target`, `headingPath?` (array incl. H1), `projectName` |
| `write` | Append to file, or insert under a heading via `headingPath` | `target`, `content`, `headingPath?`, `createMissing?`, `mode`: append/overwrite (no overwrite with headingPath) |
| `edit` | Replace `oldString`→`newString`; scoped to a section via `headingPath` | `target`, `oldString`, `newString`, `headingPath?` |
| `delete` | Delete by `timestamp`, or by `oldString` within a section via `headingPath` | `target`, `timestamp` XOR (`headingPath` + `oldString`) |
| `search` | Semantic search (global memory + current project; `projectName` targets a specific project) | `query`, `max_results` (optional), `projectName` (optional) |
| `list` | List all files (root + project folders) | - |
| `reindex` | Rebuild the search index (global memory + current project + orphan-GC; other projects self-heal lazily) | - |
| `harvest` | Manually spawn the memory-keeper for THIS session now (bypasses all trigger gates; the only trigger in manual/minimal mode) | - |

> Removed this session: `daily` target, `date` and `period` parameters (daily-log era).

**Single-writer mode (keeper enabled, default):** write/edit/delete on `project`/`corrections`/`environment` are rejected from non-keeper sessions (guard in tool execute → teaches the `<mem></mem>` protocol instead). Reads/index/search unaffected. Keeper-disabled mode restores full multi-writer behavior + the legacy instruction variant (`MEMORY_AWARENESS_INSTRUCTIONS_NO_KEEPER`).

### npm 403 issue (SOLVED — do not regress)

`npm install @opencode-ai/plugin@beta` (or any upgrade from the registry) fails with **403 Forbidden**:
the scoped package's beta dist-tag is not publicly fetchable from npmjs.org in this environment.

**Fix applied in `package.json`:**

```json
"peerDependencies": {
  "@opencode-ai/plugin": "^1.18.27 || >=2.0.0-beta"
},
"peerDependenciesMeta": {
  "@opencode-ai/plugin": { "optional": true }
}
```

- `optional: true` is critical: npm 7+ auto-installs peer deps, which would trigger the same 403 on fresh installs.

## Gotchas & Lessons Learned (from this session)

1. **PowerShell:** `&&` is not a valid statement separator in this environment — use `;`.
2. **vector-store.ts** routes by segment, not substring (since 2.1.0): `path.relative(getMemoryDir(), filePath).split(path.sep)[0] === "project"` → project index, else root index. Backslash-safe and immune to project-named ancestor dirs. The OLD `/project/` substring probe missed `\project\` (Windows separators) — live root.index was found with 19/25 chunks mis-filed from `project\opencode-auto-mem\*` (Bug E, now self-healing on upsert).
3. **MemoryManager listing:** `readDirFiles()` lists `.md` files; `readDirFolders()` lists directories. `listFiles()` now returns project *folder* names, and `embedAllExistingFiles()` iterates each folder collecting its `.md` files.
4. **Project templates auto-create** on any access to `project`/`corrections`/`environment` targets (guard in `index.ts` execute). Templates are only written if the file doesn't already exist.
5. **BootstrapManager owns no fs logic** — everything delegates to `this.memoryManager.*`.
6. **`getPathForTarget(target, projectName?)`** — the `date` parameter is gone; all project targets share the project-name resolution (`args.projectName ?? getCurrentProjectName()`).
7. **Editor tool limit:** keep `old_text`/`new_text` under ~6000 chars; split large rewrites into chunks.
8. **Server-plugin answers come from the installed SDK's `.d.ts` files**, not from `opencode-plugin-creation-doc/` (that folder documents V2/TUI/Effect APIs).
9. **Behavioral guidelines live ONLY in `memoryInstructions.ts`** — never embed them in file templates (they'd be injected twice: once via file content, once via instructions). MEMORY_TEMPLATE is pure section structure.
10. **`buildContext()` must never throw** — any new fs-creating code inside it (e.g. `createProjectTemplates`) must be wrapped in try/catch; a throw would break every session's system prompt.
11. **DUAL-RUNTIME GOTCHA — `__dirname` (HARDENED 2026-09-09):** `dist/embedding.js` used `__dirname` although the package is `"type": "module"`. Under **Node** (test harness) every embed threw `__dirname is not defined`, swallowed as `[embedding] Failed to embed ...`; under the **live OpenCode host** (Bun — CJS globals exist in ESM files there) the same code ran fine. **Fix:** `getModelCachePath()` is now `import.meta.url`-derived (exported for tests — test (h1) asserts it resolves under plain Node) and `pipeline()` passes `cache_dir` explicitly at that computed path. The harness embedding failures now show the CORRECT offline error (`env.allowRemoteModels=false and file was not found locally`) instead of the CJS throw — embedding runs through the normal transformers path under Node too. Never conclude "embedding is broken in production" from harness failures alone — the offline gate is the designed isolation.
12. **MODEL-CACHE CHAIN (FIXED 2026-09-09 alongside Gotcha 11):** the old `dirname(dirname(__dirname)) + node_modules\@huggingface\transformers\.cache` arithmetic computed a nonexistent double-node_modules path in BOTH layouts, making `isModelCacheValid`/`clearModelCache` dead code and `pipeline()` run without `cache_dir` (transformers fell back to its package-dir default — where the 522MB fp32 `model.onnx` actually lives). **Fix:** `getModelCachePath()` is `import.meta.url`-derived — deployed: `<config>/node_modules/opencode-auto-mem` → parent = `<config>/node_modules` → cache = `<config>/node_modules/@huggingface/transformers/.cache` (the REAL live cache); workspace: `<repo>/node_modules/...` — and `pipeline()` now passes `cache_dir: getModelCachePath()` explicitly. The cache-validity/corruption-retry logic targets real files. With `dtype: int8`, the first live search downloads `model_quantized.onnx` (~130MB) ONCE into that dir; the fp32 file stays. `npm install`/redeploy of a new transformers version can still wipe the cache (it lives inside a package dir).
13. **Vectra 0.12.3 stores items as plain JSON files (`<index>/index.json`), NOT SQLite** — despite the "SQLite" phrasing older docs used. Each `LocalIndex` caches `_data` in memory and NEVER re-reads disk after load: within one process, writes via OTHER instances are invisible. Test corollary (suite-proven): seeding via a separate instance then asserting a heal through the module-cached instance requires `closeIndexes()` to simulate the cross-restart boundary that production guarantees by construction. Also: **`console.*` never reaches opencode.log** — the live 2.0.2 log scan found zero plugin console lines; only `plog`'s `client.app.log()` sink does (Bug D motivation, now fixed in 2.1.0).
14. **Test harness env-isolation recipe (Windows, all in `tests/smoke-test.mjs`):** redirect BOTH `process.env.APPDATA` and `process.env.USERPROFILE` to a fresh `os.tmpdir()` dir BEFORE the first `await import()` of any dist module (`os.homedir()` reads USERPROFILE per call; `dist/vector-store.js` captures index paths at module load — ESM cache makes import order mandatory; import via `pathToFileURL(...).href`). Force offline embedding via `env.allowRemoteModels = false` on the transformers namespace BEFORE dist import. Always finish KeeperManager tests with `onKeeperIdle('k1')` or the 5-min watchdog keeps the process alive. Never call `ensureGitRepo()` while a fire-and-forget `gitCommit()` is still in the chain (concurrent `git init` "File exists" race) — drain with a chained `gitCommit('probe')`.
15. **husky pre-commit is broken in this environment and repo:** the v9 shim resolves `sh` to a WSL relay (`execvpe /bin/bash` fails), AND prettier `format:check` fails on all pre-existing src files (prettier was never run repo-wide). All commits use `--no-verify` — the hook intent (build + tests green) is satisfied manually. Fixing = run `npm run format` repo-wide + fix the WSL shim; until then, do NOT trust a green commit as proof the hooks ran.
16. **Editor tool insert-anchor quirk:** when inserting a new test before the `}],\n];` array-close anchor, re-emit the consumed anchor at the START of `new_text` — otherwise the previous test loses its closing brace (hit twice this session; one syntax-error round-trip each time).
17. **Orphan-timestamp rule (todo 10, locked):** a `<!-- ts -->` comment whose region up to the next ts/heading/EOF holds only whitespace is an orphan and is stripped — even mid-chain (ts1 directly followed by ts2). Applied only on the section-delete path (`stripOrphanTimestamps` in `timestampParser.ts`, wired into `replaceInSection`); never strips preamble or content-bearing stamps.
18. **CRITICAL — No embedding at startup OR on writes (2026-09-08, 2.2.0 fix):** `embedAllExistingFiles()` must NEVER be called at plugin boot (ONNX model + ORT arena load starves the bun event loop → black-screen TUI). It must ALSO never be triggered from write/edit/delete paths: with the keeper enabled, project memory is written after EVERY turn, so write-path embedding made the ONX native heap churn continuously (memory climbing 1-5GB within 5-10 min of use). **Fix (final design):** the ONLY automatic embedding trigger is `MemoryManager.ensureIndexed()`, called from `semanticSearch()` right before querying — it runs `embedAllExistingFiles()` + `embeddingQueue.drain()`, which is INCREMENTAL (upsertFile dedupes by chunk hash, so unchanged files cost only re-read + hash). Writes touch only .md files. The explicit `reindex` tool clears + rebuilds. `embedding.ts` passes ORT `session_options: { enableCpuMemArena: false, enableMemPattern: false }` and uses `dtype: "int8"`. `hashContent` moved to `src/hash.ts`; `embedText` dynamically imported in `semanticSearch` — boot module graph contains NO reference to `@huggingface/transformers` (which eagerly `require("onnxruntime-node")`s at import, verified `transformers.node.cjs:7631`).
19. **REAL DEPLOY TARGET — USERPROFILE config NOT APPDATA (2026-09-08, cost the user a 3-5GB spike):** OpenCode registers the plugin in `~/.config/opencode/opencode.jsonc` as `file://C:/Users/Yousaf Khan/.config/opencode/node_modules/opencode-auto-mem` — the plugin MUST be deployed to `C:\Users\Yousaf Khan\.config\opencode\node_modules\opencode-auto-mem\dist`, NEVER `%APPDATA%\opencode\node_modules\opencode-auto-mem` (a no-op; OpenCode never reads there). The memory DATA also lives at APPDATA (`%APPDATA%\opencode\memory`, per `getMemoryDir()`), but the installed plugin code is in USERPROFILE's `.config`. Goes without saying the 2.2.0 "no embed at boot" fix did nothing until deployed to the REAL location.
20. **PROJECT-SCOPED INDEXING & SEARCH (2.4.0):** one Vectra index per scope — `memory/indexes/root/` (global files) + `memory/indexes/projects/<name>/` (one per project). A project's index is opened/queried/refreshed ONLY when that project is being worked in (or explicitly searched via the `projectName` search arg); `indexing.scope: "all"` in keeper-config.json restores the legacy cross-project behavior. A file's index follows deterministically from its path (`getProjectNameForFile` in `vector-store.ts`), so cross-project mis-filing is impossible by construction — the only remaining self-heal is the root-index purge in `upsertFile`. Legacy `root.index`/`project.index` dirs are ignored and deleted on the first `reindex`. `debouncedWrite` tracks dirty scopes (root flag + project set) and refreshes ONLY those — not the whole memory tree. `reindex` = clear + rebuild root + current project + orphan-GC (`gcProjectIndexes`); other projects' indexes self-heal lazily on their own next search.
